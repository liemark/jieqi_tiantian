# jieqi_tiantian
整个项目 YOLO 模型由生成的数据集训练，其它的 UI 和 Readme 都是 DSH 写的  
用 YOLO 识别「天天象棋」的揭棋画面，把局面转成皮卡鱼揭棋引擎
（`pikafish-bmi2.exe`，[Pikafish jieqi 分支](https://github.com/official-pikafish/Pikafish/tree/jieqi)）
所需的 FEN，实时分析并给出评分、中文着法与棋盘箭头。

## 识别原理与容错

**棋盘框 → 网格。** 模型的 `board` 框左上/右下角是「最左上棋子中心」和「最右下棋子中心」，
所以格距 = `(x2-x1)/8`、`(y2-y1)/9`，真正的棋盘还要往外半个格。程序用检测到的棋子中心
做一次最小二乘精修（限幅 ±15%），并统计网格误差 `grid_fit_err` 作为置信度的一部分。

**棋盘外被吃子 → 忽略 + 反推暗子池。** 程序把落在棋盘矩形（外扩 0.6 格）之外、
但在 3 格以内的棋子归入「被吃子区」；落在棋盘矩形内但没对上交叉点的检测
（`POS_TOL = 0.42` 格）直接丢掉，既不算棋子也不算被吃子。被吃子区还会做一次跨类别去重，
再用「每方盘面外恰好缺 `16 − 盘面棋子数` 个」这个硬约束筛一遍，
所以阈值可以放低（0.25）而不怕误检污染暗子池。

**整屏抓取的 ROI 裁剪。** 整屏送进 640x640 会丢细节——实测 1920x1080 下棋盘只有 347px 宽时
直接识别会漏掉将/帅。程序在拿到两次棋盘框之后，把「棋盘 + 被吃子区」裁出来单独送网络，
等效分辨率提高 1.5~2 倍、速度也更快；连续 5 帧找不到棋盘框就自动退回整幅画面。

**暗子颜色纠错（黑/暗红混淆）。** 揭棋的暗子一旦移动就会翻开，所以暗子**必定**停在
30 个初始格上，而红方与黑方的初始格集合互不相交。程序完全无视 YOLO 给出的
`black_an` / `red_an`，只用格子坐标决定颜色；出现在非初始格的「暗子」会被判为误识别并剔除。

**朝向先判定，再判暗子颜色。** 先用 **将 / 帅**（揭棋里永远是明棋，最可靠）定朝向 → 把坐标转到标准朝向 →
才查初始格决定暗子颜色。优先级：将帅同时找到 → 单方将帅位置 → 已翻开明子分布 → 默认。

**暗子颜色纠错（black_an / red_an 混淆）。** 揭棋的暗子一旦移动就会翻开，所以暗子**必定**
停在 30 个初始格上，而红方与黑方的初始格集合互不相交。程序完全无视 YOLO 给出的
`black_an` / `red_an`，只用（标准朝向的）格子坐标决定颜色；出现在非初始格的「暗子」
会被判为误识别并剔除。

**缺将 / 帅 = 识别不可靠。** 揭棋里将/帅永远不会消失（被吃 = 对局结束），所以某一方找不到
将/帅时直接标为识别错误、不刷新局面。这同时兜住了「朝向判错」这一类问题。

**走子提示白圈（`white_point`）。** 天天象棋的走子提示是一圈白点，旧模型（17 类）会把它认成
棋子。新模型（18 类）把它单独作为一个类，`jq_detect` 会把它**完全隔离**：不参与网格拟合、
不进棋盘、不算被吃子，只在预览里画个紫框。

**数量校验与自动修复。** 每方最多 16 子，车马相仕炮各 ≤2、兵 ≤5、将帅 ≤1。超限时按
置信度从低到高删除最可疑的检测，并降低整体置信度。校验不通过时不会刷新局面，
只在状态栏提示「识别不可靠」，避免把错局面喂给引擎。

**双帧确认 + 规则校验 + 观察期。** 连续两帧识别结果完全一致才算「稳定」，避免走子动画中途
触发误判；稳定后与当前局面比较，要求同时满足：

* 恰好「N 格走空 + N 格落子/吃子」（揭棋每步必定如此），N ≤ 4；
* 棋子总数只可能不变或恰好少 1（吃子）；
* 走法符合揭棋规则（暗子按初始格兵种走，士可出九宫、象可过河）。

全部满足才判定为一步棋。否则进入 2.5 秒观察期，
期间局面保持不变才强制同步并在状态栏标注「存疑/强制同步」，绝不悄悄改局面。

**执方是算出来的，不是简单取反。** 只按奇偶取反的话，一旦漏识别一步导致执方整体反了，
后面每步都取反、就会**一直反下去**。所以改成看「这一步动的是哪一方的子」——
动子颜色是绝对的，单步时直接由它决定下一手归谁，因此**下一步就能自动纠回来**。
连续多步时按多数颜色判断先走方（连续 N 步里先走那方出现 ⌈N/2⌉ 次），
偶数步打平时才退回按原执方取反。

**连线那一刻的行棋方**：把画面和「揭棋初始局面」比——

| 局面 | 判定 |
| --- | --- |
| 一步没走 | 红先 |
| **只走了一步**（常见：对方执红，在识别到之前就已经先走了一步） | 由动子颜色决定 → 轮到黑 |
| 离开局较远、判断不出来 | 按约定默认红先 |

猜错也没关系：下一次识别到走子会按动子颜色自动纠正。任何时候都能点「换执方」手动指定，
手动指定过之后本次连线不再自动推断。
